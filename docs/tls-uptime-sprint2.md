## 1. SR-003 / TC-SEC-03: Transport security

Targets: `https://bep-backend.onrender.com` (API) and `https://bep-frontend.onrender.com` (UI).
Date of checks: 3 Nov 2026.

### 1.1 External TLS scan (Qualys SSL Labs)

| Host | Grade | Protocols offered | Forward secrecy | Known vulnerabilities flagged |
| :--- | :--- | :--- | :--- | :--- |
| bep-backend.onrender.com | **A** (both endpoints) | TLS 1.2, TLS 1.3 | Yes | None (Heartbleed, POODLE, FREAK, Logjam clear) |
| bep-frontend.onrender.com | **A** (both endpoints) | TLS 1.2, TLS 1.3 | Yes | None |

Certificate (backend): subject `CN=onrender.com` (Render's shared wildcard certificate), issued by Google Trust Services (`CN=WE1`), valid 21 Sep 2026 to 20 Dec 2026.

Result: only TLS 1.2 and TLS 1.3 are offered (the requirement is TLS 1.2 or later). The certificate is publicly trusted and in date.

To reproduce, open `https://www.ssllabs.com/ssltest/analyze.html?d=bep-backend.onrender.com` (and the frontend host) and use "Clear cache". Attach a screenshot of the summary to the Jira card as evidence.

Note: the team laptop's antivirus re-signs HTTPS traffic, so a browser certificate viewer on that machine is not valid evidence. The external scan above is the evidence.

### 1.2 HTTP to HTTPS redirect

Opening `http://bep-backend.onrender.com/health` in a browser ended on `https://bep-backend.onrender.com/health` with `{"status":"ok"}`. Render redirects plain HTTP to HTTPS at its edge. Credentials are sent only in API calls from the frontend, which uses an `https://` base URL, so they are never sent over HTTP.

Limitation: browsers may upgrade the URL themselves, so this check does not prove the server-side redirect on its own. Confirm with `curl -I http://bep-backend.onrender.com/health` from any machine that allows it (expect a 301 with a `Location: https://...` header).

### 1.3 CORS is restricted to the configured frontend

- The API only allows origins listed in the `CORS_ORIGINS` setting (`backend/app/main.py`, `CORSMiddleware`). It is configured per environment (Render dashboard), not hard-coded.
- From `https://bep-frontend.onrender.com`, a browser request to `https://bep-backend.onrender.com/health` succeeded (HTTP 200).
- From a different origin (the team's Jira page), the same request was blocked by the browser (CORS failure).

### 1.4 No secrets in the repository

- `render.yaml` stores no secret values. `JWT_SECRET` is generated by Render (`generateValue: true`), `DATABASE_URL` comes from the Render database (`fromDatabase`), and other values use `sync: false` so they are entered in the dashboard.
- `.gitignore` excludes `.env` and `.env.*` (except `.env.example`). `git ls-files` lists no `.env`, `.pem` or `.key` files.
- A pattern search of the tracked files for database URLs with passwords, private keys, API keys and Render database host names found only dummy values in test fixtures (`tests/test_config_database_url.py`).
- The Render deploy hook URL is kept as a GitHub Actions secret (`RENDER_DEPLOY_HOOK_URL`).
